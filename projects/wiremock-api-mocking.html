Problem and purpose

A provider's sandbox will not drop a connection halfway through a response, or answer 429 on the second attempt, when a test needs it to. Those failures are where integrations go wrong, and in payments they can charge a customer twice. This project makes every one of them repeatable, in seconds, with no Docker and no network.

Architecture

JUnit tests ──► CheckoutService ──► ShippingClient ──GET /v1/rates────► WireMock (carrier)
                     │
                     └───────────► PaymentClient ──POST /v1/payments──► WireMock (provider)

Engineering decisions and approach

  • A payment has three outcomes: after a timeout the client cannot know whether the money moved, so the result is unknown, never failed
  • One idempotency key per order, not per attempt, so a retry cannot become a double charge
  • Retry only what can change: 429 and 5xx, not other 4xx answers
  • Shipping degrades and payment does not: one attempt, then a flat rate marked as estimated
  • Stub objects, the page object of API mocking: tests read as behaviour and WireMock stays in one class per API

Test scope and execution approach

Project-specific checks and execution details documented in the repository:

  • Request matching on headers, query parameters and exact JSON bodies
  • Response templating: the answer is built from the request
  • Stateful scenarios for retries, Retry-After handling and exponential backoff, with the waits themselves asserted
  • All four WireMock network faults, and fixed delays against real timeouts
  • Stubs as JSON mapping files with priorities, and record and replay
  • Eight deliberate client bugs, all caught; one survived at first, because WireMock decodes + and %20 alike, and the test now checks the raw URL
  • Design notes, 35 manual test cases and 60 interview questions on API mocking (Markdown + PDF)

Known limitations

  • The APIs are invented, modelled on common payment and carrier APIs
  • A mock cannot notice a real API changing: contract tests cover that, as in the Pact project
  • HTTP/1.1 on localhost: TLS, proxies and real network timing are not covered
  • The payment and shipping APIs are invented; a mock cannot notice a real API changing, which is what contract tests are for.
