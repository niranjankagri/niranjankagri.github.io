Problem and purpose

Between unit tests and end-to-end tests sits the layer where many production bugs live: a migration that fails on the real database, an event with a wrong field, a consumer that stalls on one bad message. This project tests exactly that layer, with real infrastructure per run instead of mocks, an in-memory database or a shared test environment.

Engineering decisions and tradeoffs

  • Real PostgreSQL and Kafka, because H2 and mocked brokers hide exactly what breaks: SQL dialect, constraints, partitions, redelivery
  • One cached Spring context for every test class, so the containers start once per run
  • Unique data per test instead of cleanup: no order dependence, ready for parallel runs
  • Awaitility polls for the expected state; absence is proven by waiting for a later event on the same partition
  • Idempotent consumer: event id recorded in the same transaction as the change
