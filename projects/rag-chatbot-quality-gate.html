A help-desk chatbot for a fictional climbing gym behind a FastAPI API, with staff-only secrets and a planted prompt injection in its knowledge base. Weekly, real local models answer and judge through Ollama in CI, and the run records where the model invents and where the judges disagree.

Problem and purpose

The assistant is Belay, the help desk of a fictional climbing gym. It answers from 16 public help sections and cites them. The knowledge base also holds 3 staff-only sections with a door code and members' phone numbers, and a forum post with a prompt injection, so there is something real to protect.

The gate is honest about what it measures. Core questions written from the help articles pass at 100 %, which only shows the system does what it was built for. Reworded questions are the real number: 7 of 14 get "I don't have that information" and 2 get a confident wrong answer, but every answer stays grounded in its citation. Those cases run as strict expected failures, so the list cannot go stale.

Technology and tools

Models (weekly)llama3.2:3b answers, qwen2.5:7b judges, nomic-embed-text vectors, all local through Ollama on the CI runner
CIGitHub Actions: the offline gate on every push and pull request; the real-model run weekly with its own gate

Engineering decisions and approach

  • The required gate uses an extractive generator that cannot invent, so it tests the system around the model and is repeatable
  • One set of case files and graders feeds DeepEval, Ragas and Promptfoo through adapters
  • Known misses are strict expected failures with the measured reason: the build turns red when one starts to pass
  • Limits for the reworded questions sit just below today's values: they stop it getting worse, not say it is good enough
  • A red-team fail counts only when a second grade agrees, because the judge model itself varies

Test scope and execution approach

Project-specific checks and execution details documented in the repository:

  • 8 layers in one gate: HTTP contract, retrieval, answers, attacks, Ragas reference metrics, Promptfoo black box, latency, unit tests
  • Every grader and guard shown failing on a planted bad answer
  • Weekly real-model run: DeepEval Faithfulness, Answer Relevancy and G-Eval, Ragas metrics, stability over 5 repeats, and a red-team scan
  • What the model runs found: the model invents a fee rule, the judges score the same answer 1.0 and 0.33, and temperature 0 is not determinism
  • Generated manual test case list, checked by a test so it cannot go out of date

Known limitations

  • 44 cases and 19 sections are a lab, not a production knowledge base
  • The required gate's 100 % on core questions says nothing about a model; the weekly small-model run on a CPU runner is an indication, not a measurement
  • The guards are word lists; a determined attacker can rephrase. Latency is measured in the server, not under load
  • A lab: 44 cases and 19 sections; the required gate uses a generator that cannot invent, and the weekly small-model run is an indication, not a measurement.
