Pattern Shop: a Shared Demo App for Test Frameworks

Sign-in, products, cart and checkout pages with a data-testid on every element a test needs, and the same catalog through REST/JSON, a SOAP-style XML API and a legacy text format, for adapter and contract tests. JDK only, no dependencies.

Problem and purpose

Public demo sites are shared, slow, change without notice, and sometimes add bot checks. A framework that tests one of them is partly testing the internet. Pattern Shop is an application I control: same data on every run, no other users, and features added on purpose, such as an API in three formats for adapter tests.

Architecture

framework CI job ──► docker run ghcr.io/.../pattern-shop-demo-app ──► tests against localhost:8080
                     (fresh shop per job: fast, no shared data, never down)
people, demos    ──► hosted demo on Render (https://pattern-shop.onrender.com)

Technology and tools

AreaTools
ApplicationJava, JDK HTTP server only, no dependencies; compiled for Java 21, runs on Java 25 in the image; starts in under a second
TestsJUnit 6: 19 tests over real HTTP, plus a smoke test of the built image (sign-in, cart, all three APIs)
ImageMulti-stage Docker build, non-root user, health check; published to ghcr.io as :latest and :sha-<commit>
HostingRender free plan from render.yaml, deployed only after CI passes; uptime monitored

Engineering decisions and approach

  • Framework CI never depends on the hosted copy; it runs the image
  • A data-testid on every element a test needs, so frameworks need no fragile locators
  • The same catalog as JSON in cents, SOAP-style XML in dollars and legacy text, so adapter tests have real differences to translate
  • Sessions and carts per browser session, so parallel tests never share a cart
  • The image is published only after its own smoke test passed

Test scope and execution approach

Project-specific checks and execution details documented in the repository:

  • Users for each sign-in outcome: active, locked, wrong password, empty fields
  • A test-data API that lists the demo users, for a test-data service strategy
  • A health check that needs no extra tools in the image
  • At most 10,000 sessions on the hosted copy, then it starts over
