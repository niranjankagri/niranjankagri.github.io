Playwright for Java Framework

Annotation-based page factory, a browser per thread and a context per test, API tests with their own data clean-up, and a trace, video and screenshot kept for every failed UI test.

Technologies: Playwright, Java 17, TestNG, Jackson, GitHub Actions

Source codeREADME and setupWorkflow historyReport or image

Problem and purpose

Shows Playwright in a Java/TestNG stack, the combination many Java teams move to from Selenium: UI tests on Sauce Demo, API tests on Restful Booker through Playwright's own request context, and network control in the browser.

My contribution

I built and maintain this public project, including the framework or test harness, its documentation, and the execution evidence linked here.

Engineering decisions and tradeoffs

  • One Playwright and browser per thread, a fresh BrowserContext per test: isolated, fast, safe for parallel classes
  • An annotation-based page factory gives Selenium-style declarative locators; Playwright locators are lazy already
  • No waits in tests: Playwright auto-waits, and pages only wait for one element unique to the page
  • API tests create their own bookings and delete them afterwards, so the shared demo API is left as it was
  • Login failures throw the shop's own message at once instead of timing out

Local setup and execution

mvn exec:java -Dexec.args="install"   # once: download Chromium, Firefox and WebKit
mvn clean test                        # all tests, headless Chromium
mvn clean test -Dbrowser=firefox      # chromium, firefox or webkit
mvn clean test -Dgroups=api           # one group
