17 · Quality engineering

Automation Coverage & Quality Intelligence

Reads the JUnit XML that pytest, Robot Framework, Selenium/TestNG and Playwright already write (43 real CI files in the repo) and links it to requirements: 38 of 42 sample requirements have tests, 2 critical ones have no automated test, so the release gate fails, and 4 tests are flagged as flaky candidates with the evidence.

A platform on top of existing test automation, for release decisions: requirement and automation coverage as separate, documented metrics, execution history in SQLite with flaky-test and slow-down detection, a read-only dashboard, and a CI quality gate whose exit code is 0 passed, 1 failed or 3 incomplete, so missing results can never pass. It gates its own release on its acceptance criteria.
